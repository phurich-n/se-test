ข้อ 1

ระบบใช้งานไม่ได้ ตรวจสอบเบื้องต้นอย่างไร

คำตอบ7 ขั้นตอน

เริ่มจากฝั่งผู้ใช้ก่อน แล้วค่อยๆ ไล่เข้าไปหาเซิร์ฟเวอร์ ดูภาพรวมก่อนแล้วค่อยเจาะทีละจุด

  1. ลองทำให้เจอปัญหาเองก่อนถามให้ชัดว่าใครเจอ เจอกี่คน เจอหน้าไหน กดอะไรแล้วพัง ขึ้น error ว่าอะไร เริ่มเป็นตั้งแต่เมื่อไหร่ แล้วเป็นทุกเครื่องหรือบางเครื่อง
  2. เช็กว่าช่วงนี้มีอะไรเปลี่ยนไปบ้างปัญหาส่วนใหญ่มาจากของที่เพิ่งเปลี่ยน เช่น เพิ่ง deploy เวอร์ชันใหม่ แก้ config อัปเดต library หรือ SSL กับโดเมนหมดอายุ ถ้าเจอว่าเพิ่ง deploy แล้วพังทันที ให้ rollback กลับไปก่อน ระบบจะได้กลับมาใช้ได้
  3. ดูที่ฝั่งผู้ใช้ (browser)กด F12 เปิด devtools แท็บ console ดูว่ามี javascript error ไหม แท็บ Network ดูว่า request ไหนได้ 4xx หรือ 5xx ลองล้าง cache หรือเปิดด้วย browser อื่นดู
  4. ดูเรื่องเน็ตและการเชื่อมต่อping ถึงเซิร์ฟเวอร์ไหม ชื่อโดเมนชี้ถูกที่หรือเปล่า (nslookup) SSL ยังไม่หมดอายุใช่ไหม firewall หรือ port ถูกปิดอยู่หรือเปล่า
  5. ดูที่เซิร์ฟเวอร์และตัวแอปservice ยังรันอยู่ไหม เปิด log ของแอปกับ web server ดูว่ามี error อะไร แล้วเช็กว่า CPU, RAM หรือ disk เต็มหรือเปล่า
  6. ดูฐานข้อมูลและระบบอื่นที่แอปต้องพึ่งต่อ database ได้ไหม connection เต็มหรือยัง มี query ที่ช้าหรือติด lock ไหม แล้ว API ภายนอกที่เรียกใช้ล่มอยู่หรือเปล่า
  7. แก้ให้ตรงจุด แล้วกันไม่ให้เกิดซ้ำหาสาเหตุจริงให้เจอ (root cause) ไม่ใช่แค่อาการ แก้แล้วลองซ้ำให้แน่ใจว่าหาย แจ้งผู้ใช้ว่ากลับมาใช้ได้แล้ว แล้วเพิ่ม monitoring หรือ test เพื่อให้รู้ตัวก่อนถ้าเกิดอีก
ข้อ 2

หลังจบการทำงาน ค่าของ i เป็นเท่าใด

คำตอบi = 5
โจทย์ (pseudocode)
x := 1;
i := 1;
while (x <= 1000)
begin
  x := 2^x;
  i := i + 1;
end;
TypeScript
let x = 1;
let i = 1;
while (x <= 1000) {
  x = 2 ** x;
  i = i + 1;
}
รอบx ก่อนx = 2^xix ≤ 1000?
กด Run เพื่อดูค่า x และ i ทีละรอบ
x เพิ่มขึ้นแบบ 2 ยกกำลังซ้อน (1 → 2 → 4 → 16 → 65,536) จึงวนแค่ 4 รอบ ได้ i = 5
ข้อ 3

ถ้า n = 256 หลังจบการทำงาน r มีค่าเท่าใด

คำตอบr = 2,304
โจทย์ (pseudocode)
i := n;
r := 0;
while (i >= 1) do
begin
  for j := 1 to n do
    r := r + 1;
  i := i / 2;
end;
TypeScript
let i = n;
let r = 0;
while (i >= 1) {
  for (let j = 1; j <= n; j++) {
    r = r + 1;
  }
  i = i / 2;
}
รอบiloop ในr สะสม
กด Run เพื่อดูค่า i และ r ทีละรอบ
loop นอกหาร i ครึ่งทุกรอบ ได้ ⌊log₂256⌋ + 1 = 9 รอบ แต่ละรอบ loop ในบวก r เพิ่ม 256 → r = 256 × 9 = 2,304 · Time complexity O(n log n)
ข้อ 4

หาผลรวมของตัวเลขใน Tree

คำตอบ40

บาง node เป็นตัวอักษร (D, F) และมี node ว่าง 1 ตัว จึงบวกเฉพาะค่าที่เป็นตัวเลข (เส้นประ = ไม่นับ)

กด DFS หรือ BFS เพื่อดูลำดับการเดินแต่ละ node
แบบ Recursive (DFS)
type NodeValue = number | string | null;

function sum(n?: TreeNode): number {
  if (!n) return 0;
  const own = typeof n.value === "number"
    ? n.value : 0;  // ข้าม D, F, ว่าง
  return own + sum(n.left) + sum(n.right);
}
แบบ Iterative (BFS)
let total = 0;
const queue = [root];
while (queue.length) {
  const cur = queue.shift()!; // หยิบตัวหน้าสุดออก
  if (typeof cur.value === "number")
    total += cur.value;
  if (cur.left) queue.push(cur.left); // ใส่ตัวลูกต่อท้ายคิว
  if (cur.right) queue.push(cur.right); // ใส่ตัวลูกต่อท้ายคิว
}
2 + 3 + 4 + 5 + 7 + 9 + 10 = 40 · Time O(n), Space O(h) · recursion เขียนสั้นกว่า แต่ถ้า tree ลึกมากเสี่ยง stack overflow จึงเลือกแบบ queue ได้
ข้อ 5

Design และ Normalization ตารางข้อมูลลูกค้า

คำตอบ6 ตาราง

รหัส, คำนำหน้า, ชื่อ, สกุล, ที่อยู่, บัตร ปชช, เพศ, วันเกิด, ขนาด (S,M,B), เกรด (A–D) และลูกค้าย่อยของลูกค้าหลัก

เลื่อนซ้าย–ขวาเพื่อดู diagram ทั้งหมด

1NFทุกช่องเป็นค่าเดียว แยกที่อยู่เป็นบ้านเลขที่/ถนน/ตำบล/อำเภอ/จังหวัด/รหัสไปรษณีย์ และแยกเป็นตาราง เพราะลูกค้า 1 รายมีได้หลายที่อยู่
2NFทุกตารางใช้ primary key คอลัมน์เดียว ทุกคอลัมน์จึงขึ้นกับ key ทั้งหมด ไม่มี partial dependency
3NFคำนำหน้า เพศ ขนาด เกรด แยกเป็น lookup table ไม่เก็บคำอธิบายซ้ำทุกแถว และแก้ได้ในที่เดียว
ลูกค้าหลัก–ลูกค้าย่อย ใช้ self-referencing foreign key parent_customer_id ชี้กลับไปที่ customers.customer_id · ค่า NULL = ลูกค้าหลัก · มี CHECK กันไม่ให้ลูกค้าเป็น parent ของตัวเอง · national_id เป็นข้อมูลส่วนบุคคลตาม PDPA ควรเข้ารหัสและจำกัดสิทธิ์การเข้าถึง
